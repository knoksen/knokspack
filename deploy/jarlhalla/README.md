# Jarlhalla platform deployment

This deployment profile turns Knokspack into a private Jarlhalla operations console and adds a server-side AI gateway plus a self-hosted mail stack.

## Target architecture

- `https://jarlhalla.com` — public WordPress site.
- `https://jarlhalla.com/wp-admin/` — WordPress administrator login.
- `https://admin.jarlhalla.com` — private Knokspack/Jarlhalla control plane protected by Nginx Basic Auth.
- `https://admin.jarlhalla.com/#/jarlhalla-ai` — JarlhallaAI console.
- `https://mail.jarlhalla.com/admin` — Stalwart mail administration.
- `jarle@jarlhalla.com` — primary mailbox.

Use `mail.jarlhalla.com` as the SMTP/IMAP server hostname. Do not use `admin.jarlhalla.com` as the SMTP hostname; keeping the admin UI and mail transport hostname separate avoids TLS, MX and service-discovery conflicts.

## Safe staged DNS

Create the two host records first:

```text
A      admin        45.132.114.61
A      mail         45.132.114.61
```

Do **not** publish the MX record until Stalwart, TLS, reverse DNS and outbound TCP/25 have been verified. The final MX is:

```text
MX     @       10   mail.jarlhalla.com.
```

Do not invent DKIM values. After the Stalwart domain is created, use the DNS zone generated by Stalwart as the source of truth for DKIM, SPF, DMARC, autoconfig, autodiscover, MTA-STS and TLS reporting records.

At the VPS provider, configure reverse DNS/PTR:

```text
45.132.114.61 -> mail.jarlhalla.com
```

A working PTR plus outbound TCP/25 are prerequisites for credible direct-to-MX mail delivery.

## One-command staging

From a checkout of the `jarlhalla-platform` branch on the Jarlhalla VPS:

```bash
sudo bash deploy/jarlhalla/deploy-platform.sh --all
```

The orchestrator creates the WordPress administrator, deploys the Knokspack admin portal and JarlhallaAI backend, stages Stalwart, and prepares HTTPS when the required A records already resolve to the VPS. It deliberately never changes public MX automatically.

Individual stages are also available:

```bash
sudo bash deploy/jarlhalla/deploy-platform.sh --wordpress
sudo bash deploy/jarlhalla/deploy-platform.sh --admin-ai
sudo bash deploy/jarlhalla/deploy-platform.sh --mail
```

## WordPress administrator

```bash
sudo bash deploy/jarlhalla/bootstrap-wordpress-admin.sh
sudo cat /root/jarlhalla-wordpress-admin.txt
```

The script creates or rotates the dedicated `jarle-admin` WordPress administrator and stores the generated password in a root-only file.

## Admin portal and JarlhallaAI

Create the `admin` A record first, then run:

```bash
sudo bash deploy/jarlhalla/bootstrap-admin-ai.sh
```

The script:

- installs the Python AI backend as `jarlhalla-ai.service` on `127.0.0.1:8787`;
- installs Node.js 22 and builds Knokspack as a standalone Vite application;
- publishes it to `/var/www/admin.jarlhalla.com`;
- creates an Nginx Basic Auth gate;
- proxies `/api/jarlhalla-ai/` to the loopback-only backend;
- obtains a Let's Encrypt certificate automatically when public DNS already points at this VPS.

Configure the AI provider in `/etc/jarlhalla-ai.env`.

### OpenAI

```text
JARLHALLA_AI_PROVIDER=openai
JARLHALLA_AI_MODEL=gpt-5.5
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=<server-side key>
```

The API key remains server-side and is never compiled into the React bundle.

### Ollama

```text
JARLHALLA_AI_PROVIDER=ollama
JARLHALLA_AI_MODEL=qwen2.5-coder:14b
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
OLLAMA_API_KEY=ollama
```

After changing the environment:

```bash
sudo systemctl restart jarlhalla-ai
curl http://127.0.0.1:8787/health
```

## Mail server

The mail bootstrap can install Docker Engine and Docker Compose v2 automatically on Ubuntu when they are missing:

```bash
sudo bash deploy/jarlhalla/mail/bootstrap-mail.sh
sudo cat /root/jarlhalla-mail-recovery.txt
```

The Stalwart administration service is initially bound only to `127.0.0.1:8088`. Complete the initial Stalwart setup wizard through an SSH tunnel or after configuring the Nginx proxy.

Prepare `mail.jarlhalla.com` and its certificate:

```bash
sudo bash deploy/jarlhalla/bootstrap-mail-proxy.sh
```

Install the current `stalwart-cli` from the official Stalwart CLI release, plus `jq`, then create the domain and mailbox:

```bash
sudo apt-get install -y jq
sudo bash deploy/jarlhalla/mail/post-setup.sh
sudo cat /root/jarlhalla-mailbox-jarle.txt
sudo cat /root/jarlhalla-mail-dns.txt
```

Copy the generated DNS records from `/root/jarlhalla-mail-dns.txt` into the authoritative DNS zone. The Stalwart-generated values, especially DKIM selectors and keys, must be copied exactly.

## TLS for SMTP/IMAP

Nginx/Certbot handles HTTPS for the management endpoint. Stalwart must also be configured to use a certificate covering `mail.jarlhalla.com` for SMTP submission and IMAP TLS. The Docker container mounts `/etc/letsencrypt` read-only so a Stalwart Certificate object can reference the Certbot files. After renewal, trigger Stalwart's TLS certificate reload or restart the mail container with a Certbot deploy hook.

## Security boundaries

- The JarlhallaAI backend listens only on loopback.
- AI provider secrets live in `/etc/jarlhalla-ai.env` with mode `0600`.
- The admin portal has an outer Nginx password gate in addition to WordPress's own login.
- Mail recovery and mailbox credentials are written only to root-readable files.
- Do not publish port `8088`; it is deliberately loopback-only.
- Do not remove the Stalwart recovery account until a permanent Stalwart administrator has been created and verified.
